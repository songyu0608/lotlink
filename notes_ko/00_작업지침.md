# LotLink 작업 지침 (한국어)

새 대화에서 작업을 이어갈 때 먼저 읽는 문서다. 성과물이 아니라 진행용 메모다.

## 1. 전제

- 일본에서 일하는 개발자가 안건(案件) 참가용 포트폴리오를 혼자 만든다. AI를 활용한다.
- 목적은 두 가지다: 포트폴리오 완성, 그리고 상류 工程부터 개발까지 거치며 현장 용어를 익히는 것.
- 사용 기술: Python, GitHub, AWS(가능한 범위).
- 사용자는 일본어에 능숙하다. 일본어 용어를 풀어서 번역할 필요는 없고, 처음 나오는 업무 용어만 설명한다.

## 2. 언어 규칙

| 대상 | 언어 |
|---|---|
| 성과물(docs/ 아래 전부, README, 코드 주석) | 일본어 |
| 대화, 설명 | 한국어 |
| 설명용 메모 | 한국어, `notes_ko/` 에 따로 보관 |

## 3. 역할

- Claude: 초안 작성, 선택지 제시, 용어 설명
- 사용자: 가상 고객 겸 PM. 판단과 승인을 한다.

실제 현장의 고객 ヒアリング은, Claude가 선택지를 제시하고 사용자가 고르는 방식으로 대체한다.

## 4. 스텝당 진행 순서

1. 초안 제시(일본어 문서)
2. 그 스텝에서 나온 용어 설명(한국어) → `notes_ko/02_용어집.md` 에 추가
3. 검토·수정
4. 확정 → 파일 반영 → `notes_ko/01_진행기록_결정사항.md` 갱신 → 다음 스텝

한 번에 여러 스텝을 진행하지 않는다.

## 5. 문서 작성 규칙

상세는 `docs/00_共通/02_ドキュメント規約.md` 를 따른다. 요점만 적는다.

- Markdown, 그림은 Mermaid
- ID 접두어: `BR-`(業務要件), `F-`(機能要件), `NF-`(非機能要件), `Q-`(未決事項)
- 기능마다 フェーズ(1~5) 표기
- 문서마다 改訂履歴

## 6. 응답 방식

- 결과물 먼저, 설명은 최소
- 확인되지 않은 내용은 단정하지 않고 불확실하다고 명시
- 현장마다 다른 것(문서 양식, ID 규칙 등)은 "표준이 아니다"라고 밝힘
- 최신 정보·수치는 검색으로 확인

## 7. 현재 위치

`notes_ko/01_진행기록_결정사항.md` 의 "다음 할 일"을 본다.

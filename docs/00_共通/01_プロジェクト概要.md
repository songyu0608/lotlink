## 1. プロジェクトの位置づけ

| 項目 | 内容 |
|---|---|
| プロジェクト名 | LotLink |
| システム名称 | LotLink 受注・在庫管理システム |
| 種別 | 個人開発のポートフォリオ（架空の顧客を想定） |
| 目的 | 案件参画に向けたポートフォリオの作成。要件定義から開発・テストまでを一通り経験し、工程ごとの成果物と用語を習得する |
| 体制 | 1名（AIを活用して開発） |

## 2. 想定顧客

| 項目 | 内容 |
|---|---|
| 業種 | 化粧品メーカー（架空） |
| 特徴 | 自社工場を保有し、自社ECサイトとAmazonの両方で販売している |
| 詳細設定 | `docs/01_要件定義/01_概要.md` の「2. 想定顧客」を参照 |

化粧品メーカーを選定した理由：
- ロット・使用期限の管理が必要で、在庫ロジックに業務的な専門性が出る
- 受注・引当・出荷・入荷・棚卸・ロットといった用語が、製造業の基幹システム（販売管理・在庫管理・生産管理）で共通して使われる

## 3. システムの範囲

複数の販売チャネルから受注を取り込み、在庫引当を行う仕組みを中心とする。

### 3.1 開発フェーズ

| フェーズ | 内容 |
|---|---|
| 1 | 在庫管理：商品マスタ、入出庫、ロット |
| 2 | 受注管理：自社EC注文API、Amazon注文CSV取込バッチ、在庫引当 |
| 3 | 自社EC画面（最小構成） |
| 4 | 日次集計バッチ、アーカイブ |
| 5 | （任意）工場の生産実績 → 入庫連携 |

- 要件定義は全フェーズを対象に作成する。
- 実装はフェーズ順に進める。フェーズ1〜2の完成をポートフォリオとしての最低ラインとする。

### 3.2 簡略化する範囲

| 対象 | 方針 |
|---|---|
| 決済 | 実際の決済連携は行わず、モックとする |
| Amazon連携 | 実APIは使用せず、注文CSVの取込で代替する |
| 自社EC画面 | 商品一覧、カート、注文の3画面に限定する |

## 4. 技術構成（案）

基本設計で確定する。現時点では案である。

| 区分 | 技術 |

| CI/CD | GitHub Actions + pytest |

## 1. 本書について

本書は、LotLink 受注・在庫管理システム（以下「本システム」）の要件定義書のうち、概要を記載する。

本書に記載する顧客および数値は、ポートフォリオ作成のために設定した架空のものである。

## 2. 想定顧客

| 項目 | 内容 |
|---|---|
| 呼称 | A社（架空） |
| 業種 | 化粧品メーカー |
| 従業員数 | 約300名 |
| 拠点 | 自社工場 1か所、物流倉庫 1か所 |
| 取扱商品 | 約200 SKU |
| 販売チャネル | 自社ECサイト、Amazon、卸売 |
| 現行システム | 卸売向けの販売管理システムがある。EC向けの在庫は、Excelと各チャネルの管理画面で手作業により管理している |

## 3. 背景

A社は、卸売に加えて自社ECサイトとAmazonで商品を販売している。EC向けの在庫管理には、次の問題がある。

| No. | 問題 | 原因 |
|---|---|---|
| 1 | 実際の在庫数を超えて注文を受けてしまう（売り越し）ことがある | 在庫数を自社ECサイトとAmazonで別々に管理しており、一方で売れた分をもう一方へ手作業で反映しているため、反映が遅れる |
| 2 | 在庫数の更新と受注内容の転記に手間がかかり、入力の誤りや漏れが起きる | Excelと各チャネルの管理画面の間で、同じ内容を手作業で入力している |
| 3 | どのロットの商品をどの注文に出荷したかを追跡できない | EC向けの出荷では、ロットと使用期限を記録していない |
| 4 | 現行の販売管理システムでEC向けの受注を扱えない | 現行システムは卸売向けに作られており、ECの受注を取り込む機能がない |

## 4. 目的

自社ECサイトとAmazonの受注および在庫を1つのシステムで管理し、売り越しを防止する。あわせて、ロット単位で出荷を追跡できるようにする。

## 5. 狙い

本システムの導入により、次の効果を期待する。

| No. | 期待する効果 | 対応する問題 |
|---|---|---|
| 1 | 販売チャネルをまたいだ在庫の一元管理により、売り越しを防止する | 1 |
| 2 | 受注の取込と在庫数の更新を自動化し、手作業と入力の誤りを減らす | 2、4 |
| 3 | 出荷した商品のロットを記録し、回収が必要になったときに対象の注文を特定できるようにする | 3 |
| 4 | 使用期限の近いロットから出荷し、期限切れによる廃棄を減らす | 3 |

効果の目標値（件数、時間など）は設定していない。

## 6. スコープ

### 6.1 対象

| 区分 | 内容 | フェーズ |
|---|---|---|
| 在庫管理 | 商品マスタ、入庫、出庫、ロットと使用期限の管理 | 1 |
| 受注管理 | 自社ECサイトの受注、Amazonの注文CSVの取込、在庫引当、出荷の登録 | 2 |
| 自社ECサイト | 商品一覧、カート、注文の3画面 | 3 |
| 集計・保管 | 日次集計、古いデータのアーカイブ | 4 |
| 生産実績の連携 | 工場の生産実績を入庫として取り込む | 5（任意） |

### 6.2 対象外

| 内容 | 扱い |
|---|---|
| 卸売の受注・出荷・請求 | 現行の販売管理システムで継続する |
| 決済処理 | 実際の決済連携は行わず、モックとする |
| AmazonとのAPI連携 | 注文CSVの取込で代替する |
| 生産管理（生産計画、原材料の管理） | 対象外。生産実績の取込のみフェーズ5で扱う |
| 配送業者との連携（送り状の発行など） | 対象外 |
| 返品・交換 | 対象外 |
| 会計 | 対象外 |
